# DayBrief

### AI 기반 정보 요약 자동화

코디세이 AI 네이티브 Final Project · 16조


저장소: https://github.com/lisap127-oss/M3-1_FinalProject


---

## 매일 아침, 같은 일을 반복합니다

- 포털·뉴스레터·SNS에 흩어진 정보를 직접 골라내는 데 **하루 20~30분**
- 출근·등교 전 짧은 시간에 관심 분야 핵심만 파악하기 어려움
- 일반 뉴스레터는 **모든 구독자에게 같은 내용**을 보냄

> "정보를 읽는 시간"이 아니라 **"무엇을 읽을지 고르는 시간"**이 문제다


---

## DayBrief가 하는 일

**관심 키워드를 등록하면, 매일 아침 나에게 맞는 뉴스 브리핑이 메일로 온다**

1. 언론사 RSS에서 기사 수집
2. AI Agent가 키워드별 주요 기사 **선별 · 요약**
3. 매일 아침 **이메일 자동 발송**
4. 좋아요 / 관심없음 피드백을 **선호도로 누적**
5. 다음 브리핑의 기사 선정에 반영

→ 쓸수록 내 관심사에 맞춰지는 브리핑

## 범위를 좁혔습니다

멘토 피드백: *"6주 안에 다 만들려다 전부 어설퍼진다"*

| 구분 | 내용 |
|---|---|
| **Must** | 키워드 설정 · 뉴스 수집 · AI 요약 · 이메일 발송 · Long-term Memory |
| **Should** | 피드백 수집, 웹 브리핑 생성 |
| **Won't** | 메일함 요약(OAuth 복잡), 저녁 리포트(중복), 카카오톡(API 제한) |

**"뉴스 → 요약 → 이메일"** 한 줄기를 완성하고, 거기에 개인화를 더하는 전략

## 필수 기술 요소 ① AI Agent

**뉴스 선별 · 요약 Agent**

- 입력: 사용자 키워드 + 주제별 선호도 + 수집 기사
- 중요도 평가 (0~100점)
  - 관련성 40 · 정보 가치 30 · 최신성 20 · 실용성 10
- 출력: 선정 기사 · 2문장 요약 · 중요도 · **선정 근거** · 제외 사유 (JSON)

**환각 방지 규칙**
원문에 없는 사실·수치·발언 생성 금지 / 입력된 기사 ID만 사용 / 출처·URL 원본 보존


---

## 필수 기술 요소 ② Long-term Memory

**피드백이 쌓일수록 정교해지는 개인화**

- 좋아요 **+1** / 관심없음 **-1**, 점수 범위 **-5 ~ 5**
- Supabase에 현재 선호도와 피드백 이력을 분리 저장
- 선호도 갱신과 이력 기록을 **하나의 트랜잭션**으로 처리

**선호도를 남용하지 않는 설계**

- 선호도는 중요도 점수에 **합산하지 않음** (보조 기준)
- 선호도가 낮아도 중요한 기사는 선정될 수 있음


---

## 필수 기술 요소 ③ 자동화 워크플로우

**매일 07:30 KST · GitHub Actions**

```
RSS 수집 (8개 피드, 약 550건)
   → 구독자별 필터링 (24시간 · 키워드 매칭 · 중복 제거 · 최대 15건)
   → AI 요약 (5건씩 분할 요청)
   → 이메일 발송 (HTML + 텍스트, 중요도순)
```

- 요약 실패 묶음은 **반으로 나눠 재시도**
- 한 구독자가 실패해도 **나머지 구독자는 계속 처리**
- 매칭 기사가 없으면 LLM을 호출하지 않음 (API 사용량 절감)

## 기술적 의사결정

| 선택 | 이유 |
|---|---|
| 네이버 검색 API → **언론사 RSS** | 신규 신청 중단 + 약관상 AI 요약·자동 수집 금지 |
| **Groq** `gpt-oss-20b` | OpenAI 호환 인터페이스로 교체 비용 낮음, 배치 처리에 충분한 속도 |
| n8n → **GitHub Actions** | PC 상태와 무관, 무료, 실행 기록이 남음 |
| Next.js → **정적 HTML/CSS/JS** | 배포를 단일 서비스로 유지, 프록시·CORS 불필요 |
| **Gmail 앱 비밀번호** | 발송 권한만 부여, 유출 시 해당 비밀번호만 폐기 |

기획서 대비 변경 사항은 모두 **실행 과정에서의 제약**에 따른 판단입니다.

## 문제 해결 기록

| 증상 | 원인 | 해결 |
|---|---|---|
| 요약 API 502 | 추론 토큰이 응답 한도를 소모해 JSON 잘림 | 5건 단위 분할 + 실패 시 재분할 |
| SMTP 연결 끊김 | 실제로는 로그인 거부(535), 앱 비밀번호와 발신 계정 불일치 | 계정 일치 + 오류를 그대로 노출 |
| 날짜가 하루 전으로 표시 | GitHub 서버가 UTC 기준 | 날짜를 KST로 계산 |

**자동 테스트 56개 통과** — 네트워크·LLM·SMTP를 모의 처리해 키 없이 실행
